# Observatory (branch `observatory`, not deployed)

- `data/agents/*.json`: copy of `qtorb/rosmarops-vigil` @ c51dde8, `data/observatory/agents/`. Validated in CI against `schema/observatory.v1.schema.json` (same commit).
- `i18n/{en,es,ca}.json`: fixed texts of the templates. EN is the source; ES and CA must have exactly the same keys (the build stops otherwise). Verified by the product advisor and signed by Albert on 2026-10-28 (commit 0d29ab1 texts).
- `build.py`: standard-library generator. `python3 observatory/build.py` writes `site/observatory/`, `site/es/observatorio/`, `site/ca/observatori/` and the JSON files. An agent page is generated only when the agent has at least one entry in `changes` or `ratings`. Ratings are never rendered.
- Every page carries `noindex` and nothing is added to sitemaps or `llms.txt` while `NOINDEX = True`.
- `tests/fixture/`: one synthetic agent, used only by CI to render the agent page template. Never copied to `site/`.
- The deploy workflow only runs on `main` and uploads an explicit file list, so nothing here reaches the server.
- `sources.json`, `collect.py`, `schema/raw.v1.schema.json` (GTM-75): the single list of fixed sources F1–F28 and the collector that reads them without a model. `.github/workflows/observatory-collect.yml` runs it daily at 05:30 UTC and commits `raw/<date>.json` (Madrid date) to `main`. Test phase: nothing reads `raw/` yet.
- `data/lab/manifest.json` (GTM-182): the `manifest.json` of the sandbox lab release in use (qtorb/rosmarops-lab, today `lab-20261118-2`), copied unchanged. Only the PNGs of its `concluyente` entries are copied, to `site/assets/sandbox-lab/`, after checking each SHA-256 against the manifest; the `.txt` files and the `no_concluyente` or `inesperado` entries are not published. `sandbox_section.py` places each capture in the guide (`/sandbox/`): the template file in step 2, `ls` and `red` in the read and network boxes, `antes` in step 1 and `despues` in step 3. A capture only goes in a box if the lab ran that box's command, and in step 2 only if it shows a file of that template; without a capture, the box keeps its example output. Each capture links to its full-size PNG and carries its real width and height, with lazy loading. The deploy uploads every PNG of that folder. `.github/workflows/lab-captures.yml` (BV-250, GTM-183) does this import once a day with `tools/lab-captures/collect.py`: if the latest lab release is not the one in `data/lab/manifest.json`, it checks the SHA-256 of every file, copies the manifest and the `concluyente` PNGs to the same places, regenerates the guide and opens a pull request for the advisor; Albert merges it.
- Families (GTM-191, schema observatory v1.15): `build.family()` puts each agent file in one of five families, in this order (`build.FAMILIES`): on your computer; agent orchestrators (`kinds` has `orchestrator`: Paperclip, Orca, Paseo, Claude Squad, Paradev); frameworks (`framework` or `agent_tooling`, without `orchestrator`); workflow automation (`kinds` has `workflow_automation`: n8n, even with `local_footprint` `no`); in the cloud and personal agents. The family is the tag of each agent in the company grid and the order of the `ItemList` blocks in the index JSON-LD. An orchestrator's page, if it ever has one, uses `agent.h1_orchestrator`. The four new orchestrators and the OpenAI Agents SDK framework are followed daily from their GitHub releases (F63-F67 in `sources.json`). An orchestrator's page uses `agent.h1_orchestrator` as its title too.
- Sandbox page (GTM-194, order and texts signed by Albert, 20-11): `/sandbox/`, `/es/sandbox/` and `/ca/sandbox/` (`sandbox_section.py`) now read in this order: the H1 and a new lead; «Why turn it on»; «What changes in your day»; «Which level to choose»; the line «Choose your agent…», the selector and the steps per agent and system (unchanged, with the lab's captures and one new line before the test boxes of step 1); the boxes «Which agents have one?» and «Trying an agent you don't know?», once; «A worktree is not a sandbox», which links to the Observatory's home; and «Questions», as folds. The page's own texts are in the Observatory catalog (`i18n/{en,es,ca}.json`, keys `sandbox.*`). «What's a sandbox?» is no longer repeated in each panel; the side column stays only in the panels of another user account. The last sentence of «Which level to choose» appears only once the Claude Code templates page exists (`/templates/`, `/es/plantillas/`; GTM-190). No new CSS or JavaScript: the sections use the site's text-page style (`.doc`) and the guide's folds.
- Template pages (GTM-190, signed by Albert on 20-11): `templates_pages.py` builds `/templates/` and `/es/plantillas/` with three question pages, one per Claude Code template (P0 read only, P1 no web, P2 sandbox), from BV-266's export of qtorb/rosmarops-templates copied into `observatory/data/templates/` (the repository's `README.md` and `claude-code/<use>/`, with `FOLDER` naming each use's folder). Until that copy exists nothing is built: no page, sitemap entry, `llms.txt` line or footer link. Same shell and styles as the sandbox guide, its copy button, no structured data, hreflang EN<->ES only. It stops the build if a page would lack its version line, its settings file or its Spanish catalog text.

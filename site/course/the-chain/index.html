The chain

A single permission doesn't tell you much. What matters is the chain: who gets in, what they can do, which keys they find and what those keys open. If one link is missing, the chain breaks.

The building's keyring

Four questions, always in the same order.

Agent

Who gets in?

The painter who comes to work in the building. Claude Code, Cursor, an MCP server: any program that can act on your computer.

Capability

What do you let it do?

Walk into the flats without knocking, only with permission, or never. Read, write, run commands, go online.

Credential

Which keys does it find?

The keys hanging in the flats it can walk into: a service's key saved in a .env file, a token, a private key.

Resource

What does each key open?

The garage, the strongbox, the bank account. Your Stripe account, your repositories, a database or another agent's configuration.

Why the order matters

  • A key on its own isn't a problem if nobody can reach it without asking you.
  • An agent with lots of permissions isn't a problem if there's nothing valuable within its reach.
  • The problem is the whole chain. And to break it, you only need to remove one link: the easiest is almost always the second one, what you let it do.

A common trap

  • Forbidding the agent to read a file cuts the direct path.
  • But if the agent can run any command without asking you, a program it launches can read that file anyway.
  • RosmarOps sees this and flags it: the chain still holds, «partly».

What you can't see

  • RosmarOps reads what each agent is allowed to do, not what it does while it works.
  • And what it couldn't read, it doesn't count as clean: it tells you it couldn't read it.

What breaks?

You change one thing on your computer. In which link of the chain does RosmarOps see it? It can be more than one, or none.

Now, on your computer

Ten minutes. Find a real chain in your own report.

  1. Run RosmarOps and open the report.

  2. Scroll down to the Findings block. Look for a problem with the word KEY above its title. Its title says something like «Your Stripe is within reach of 2 agents.»
  3. Read the line underneath: «These agents can read its keys without asking you: …». There you have the agents, the first link. And «without asking you» is the capability, the second one.
  4. Tap See the steps › (or the link in the «How to fix it» column) to go to that problem in «The detail, problem by problem». Its title says, for example, «Your Stripe key: Claude Code can read it without asking you». There you have the credential, the third link.
  5. Read the sentence that follows: «With it anyone can move money or read your customers' payments.» That's the resource, the fourth link.
  6. Write down your chain in four words: agent → capability → credential → resource.
  7. Now decide which link you would break. It's almost always the second one: the agent asking you before reading that file. The first problem in your report and the Start here card tell you how.

What if you don't have any problem marked «KEY»?

It means that, in what RosmarOps was able to read, no agent reaches a key without asking you. Also look at the line «Outside the scope of this analysis» in your report: what it couldn't read doesn't count as clean.

Sandbox: prueba un agente de IA antes de darle tus carpetas

Un sandbox es un espacio cerrado donde un agente de IA trabaja sin poder tocar lo que queda fuera: el resto de tus carpetas, tus claves o internet. Aquí ves qué agentes lo traen, cómo encenderlo en el tuyo y qué cambia cuando lo haces. RosmarOps no monta ningún sandbox: te dice qué podría tocar tu agente, con él y sin él.

Qué agentes lo traen

Casi todos los agentes de IA traen sandbox, pero casi ninguno lo trae encendido. En la tabla ves, agente por agente y sistema por sistema, si lo tiene, si viene encendido y si corta internet.

Ver la tabla

Enciéndelo en tu agente

Cada plantilla es un texto que copias y le pegas a tu agente: él te enseña el cambio y te pregunta antes de guardarlo. Enciende el sandbox, limita lo que puede leer y, donde se puede, corta internet.

Antigravity CLI

macOS y Linux

Plantilla

Añade estos ajustes a mi configuración de Antigravity CLI (~/.gemini/antigravity-cli/settings.json), sin cambiar nada más. Enséñame el cambio antes de guardarlo.

{ "enableTerminalSandbox": true, "toolPermission": "proceed-in-sandbox" }

Lo que no cubre

  • Los servidores MCP y la lectura de páginas web van por sus reglas de permisos. Los dominios que permitas para leer páginas web quedan abiertos también para las órdenes del sandbox.
  • Si dejas que una orden salga del sandbox, corre en tu ordenador con todos tus permisos.
  • Si tu sistema no tiene el sandbox que necesita, el ajuste no hace nada y no avisa.
Probar solo esta vez

Abre Antigravity CLI con el sandbox encendido solo para esta sesión: no cambia su configuración y, al cerrarlo, todo vuelve a como estaba.

agy --sandbox

Claude Code

macOS y Linux

Plantilla

Añade estos ajustes a mi configuración de Claude Code, cada uno en el fichero que indica su primera línea, sin cambiar nada más. Enséñame el cambio antes de guardarlo.

// ~/.claude/settings.json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "disableAutoMode": "disable",
    "disableBypassPermissionsMode": "disable",
    "blockReadsOutsideWorkingDirectories": true,
    "allow": [
      "Bash(npm run lint)", "Bash(npm run test *)",
      "Bash(git status)", "Bash(git diff)"
    ],
    "ask": [
      "Edit(~/.codex/**)", "Edit(**/.codex/**)",
      "Edit(~/.cursor/**)", "Edit(**/.cursor/**)",
      "Edit(~/.cline/**)", "Edit(**/.clinerules/**)",
      "Edit(~/.gemini/**)", "Edit(**/.gemini/**)",
      "Edit(~/.grok/**)", "Edit(**/.grok/**)", "Edit(~/.hermes/**)",
      "Edit(~/AppData/Roaming/**)",
      "Edit(**/AGENTS.md)", "Edit(**/CLAUDE.md)", "Edit(**/GEMINI.md)",
      "Edit(**/.github/copilot-instructions.md)"
    ],
    "deny": ["WebFetch", "WebSearch", "Bash(curl *)", "Bash(wget *)"]
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "autoAllowBashIfSandboxed": false,
    "network": { "allowedDomains": ["registry.npmjs.org", "github.com"], "strictAllowlist": true },
    "filesystem": { "denyRead": ["~/.ssh", "~/.aws"] },
    "credentials": { "files": [ { "path": "~/.aws/credentials", "mode": "deny" }, { "path": "~/.ssh", "mode": "deny" } ] }
  }
}

// .claude/settings.json
{ "sandbox": { "filesystem": { "denyRead": ["~/"], "allowRead": ["."] } } }

Lo que no cubre

  • El sandbox solo cubre la terminal. Sus herramientas para leer, editar y abrir páginas web van por fuera: la plantilla las limita con sus propias reglas.
  • Los hooks, los servidores MCP de tu ordenador y la orden de la línea de estado corren fuera del sandbox.
  • Las órdenes que pongas en excludedCommands corren fuera del sandbox.
  • Las órdenes que escribes tú con ! delante corren fuera del sandbox.
  • La plantilla deja abiertos registry.npmjs.org y github.com: lo que la terminal lea del proyecto podría salir hacia ellos.
Probar solo esta vez

Abre Claude Code con el sandbox encendido solo para esta sesión: no cambia su configuración y, al cerrarlo, todo vuelve a como estaba.

claude --settings '{"sandbox":{"enabled":true,"failIfUnavailable":true,"allowUnsandboxedCommands":false,"autoAllowBashIfSandboxed":false,"network":{"allowedDomains":[],"strictAllowlist":true},"filesystem":{"denyRead":["~/"],"allowRead":["/RUTA/DEL/PROYECTO"]}},"permissions":{"blockReadsOutsideWorkingDirectories":true,"deny":["WebFetch","WebSearch"]}}'

Linux: Necesita: bubblewrap y socat.

Cambia /RUTA/DEL/PROYECTO por la ruta de tu proyecto.

Fuente: Anthropic, leída el 16 de noviembre de 2026.

Windows

En Windows, Claude Code no tiene sandbox: ábrelo con otra cuenta de usuario del ordenador, sin tus carpetas ni tus claves.

Fuente: Anthropic, leída el 16 de noviembre de 2026.

Codex

macOS y Linux

Plantilla

Añade estos ajustes a mi configuración de Codex (~/.codex/config.toml), sin cambiar nada más. Enséñame el cambio antes de guardarlo.

default_permissions = "p2"
[permissions.p2.filesystem]
":minimal" = "read"
[permissions.p2.filesystem.":workspace_roots"]
"." = "write"
"**/*.env" = "deny"
[permissions.p2.network]
enabled = false

Lo que no cubre

  • La búsqueda web no pasa por el sandbox.
  • Las llamadas a apps y conectores van por fuera del sandbox.
  • Los servidores MCP van por fuera del sandbox.
  • El navegador y el control del ordenador (Computer Use) van por fuera del sandbox.
  • El sandbox no corta la conexión del propio Codex con su servicio.
  • Linux: Los ficheros que bloqueas se fijan cuando arranca cada orden: un fichero que se cree después se puede leer.
Probar solo esta vez

Abre Codex con el sandbox encendido solo para esta sesión: no cambia su configuración y, al cerrarlo, todo vuelve a como estaba.

codex --sandbox workspace-write -c sandbox_workspace_write.network_access=false

Cursor

macOS y Linux

Plantilla

En los ajustes de Cursor (Settings > Agents > Approvals & Execution), elige el modo «Allowlist», deja su lista vacía y enciende el sandbox.

Añade estos ajustes a mi configuración de Cursor, cada uno en el fichero que indica su primera línea, sin cambiar nada más. Enséñame el cambio antes de guardarlo.

// ~/.cursor/sandbox.json
{ "readBoundary": "workspace", "networkPolicy": { "default": "deny", "allow": ["registry.npmjs.org"] } }

Lo que no cubre

  • Las órdenes que añadas a su lista de permitidas y la descarga de páginas web corren fuera del sandbox.
  • Puede cambiar la configuración y las instrucciones de otros agentes que estén dentro del proyecto.
  • Los servidores MCP van por fuera del sandbox.
  • En Linux necesita Landlock v3; si el sistema no lo tiene, vuelve a preguntarte antes de cada orden.

Fuente: Anysphere, leída el 16 de noviembre de 2026.

Windows

En Windows, Cursor no tiene sandbox: ábrelo con otra cuenta de usuario del ordenador, sin tus carpetas ni tus claves.

GitHub Copilot en VS Code

macOS y Linux

Plantilla

En VS Code, abre los ajustes y pon:

"chat.agent.sandbox.enabled": "on",
"chat.agent.sandbox.network.allowNetwork": false,
"chat.agent.sandbox.fileSystem.allowDevToolAccess": false,
"chat.agent.sandbox.fileSystem.userConfiguredPaths": { "deniedPaths": ["~/.ssh", "~/.aws"] },
"chat.agent.sandbox.allowUnsandboxedCommands": false

Lo que no cubre

  • Las herramientas propias de VS Code que no lanzan órdenes no pasan por el sandbox: usan sus propias comprobaciones.
  • Los servidores MCP que no arranca VS Code van por fuera del sandbox.
  • Dentro del sandbox, las órdenes reciben de serie tus credenciales de git y gh.
  • Su documentación no dice si puede leer el resto de tu carpeta personal: la plantilla solo bloquea ~/.ssh y ~/.aws.

Grok Build

macOS y Linux

Plantilla

Añade estos ajustes a mi configuración de Grok Build (~/.grok/config.toml), sin cambiar nada más. Enséñame el cambio antes de guardarlo.

[ui]
permission_mode = "ask"

[permission]
rules = [
  { action = "allow", tool = "bash", pattern = "npm run lint" },
  { action = "allow", tool = "bash", pattern = "npm run test *" },
  { action = "allow", tool = "bash", pattern = "git status" },
  { action = "allow", tool = "bash", pattern = "git diff" },
  { action = "deny",  tool = "webfetch" },
]
deny = ["WebSearch"]

[sandbox]
profile = "strict"

[compat.claude]
hooks = false

[compat.cursor]
hooks = false

Lo que no cubre

  • En macOS, el sandbox no corta la red de las órdenes.
  • El sandbox no corta la conexión con el modelo ni sus herramientas web.
  • La búsqueda web puede seguir abierta: su documentación solo confirma que se corta al arrancarlo con --deny WebSearch.
Probar solo esta vez

Abre Grok Build con el sandbox encendido solo para esta sesión: no cambia su configuración y, al cerrarlo, todo vuelve a como estaba.

grok --sandbox strict --disable-web-search --deny WebFetch

Linux: Necesita: Linux 5.13 o posterior.

Fuente: xAI, leída el 16 de noviembre de 2026.

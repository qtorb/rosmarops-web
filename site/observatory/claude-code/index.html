Claude Code on Windows: what it can do on your computer

Anthropic · Terminal program (CLI), Code editor extension, Desktop app, Cloud · Reviewed on 29 October 2026

In short

As of 29 October 2026, according to its documentation, Claude Code starts in the auto mode (since Claude Code 2.1.283): what would otherwise need your permission is approved or blocked by another AI model, not by you.

By default, without asking you, it can read files in the folders it works in, run read-only commands and fetch pages from a built-in list of documentation sites.

On Windows, it keeps its configuration in 9 kinds of files. In 6 of them, keys can be written as they are, unencrypted: any program running under your user can read them.

Mode it starts in

Starting mode: auto

When an action needs permission, who gives it: another AI model.

Starting mode since Claude Code 2.1.283.

Built-in starting permission mode for interactive sessions; in auto mode a model, not the user, decides what would otherwise be asked.

Official source · accessed on 24 October 2026

Try it in a test environment

An empty folder isn't enough: most agents can read your whole home folder, keys included. This is how to limit what Claude Code could touch:

  • Windows: use its Read only profile, which stops it reading outside the project. RosmarOps's report gives it to you.
  • macOS: use its Read only profile and also turn on its sandbox, as its documentation explains.
  • Linux: use its Read only profile and also turn on its sandbox, as its documentation explains.

A sandbox limits what it could touch; it doesn't make it harmless. In many agents it limits what it writes and where it connects, but not what it reads. With the network open, what it reads could get out.

Then run RosmarOps in that same environment: you see what the agent could touch.

Security change history

Only changes that affect what it can do on your computer or with your accounts. Nothing is deleted: corrections stay on record.

  1. 25 November 2026 · version 2.1.332 · Hooks

    Before: Before 2.1.332, the Claude Code changelog listed no hook event that runs before a skill's inline shell commands.

    Now: From 2.1.332, a PreSkillShellCommand hook event can block a skill's or command's inline shell commands while it loads, according to the changelog.

    Collected automatically on 25 November 2026 from the official changelog. Official source

  2. 20 November 2026 · version 2.1.330 · Where data is sent

    Before: Before 2.1.330, the Claude Code changelog listed no sign-in to organizations managed in Enterprise Admin Console.

    Now: From 2.1.330, after claude auth login to an Enterprise Admin Console organization, Claude Code applies that organization's settings and uses its cloud provider or gateway, according to the changelog.

    Collected automatically on 21 November 2026 from the official changelog. Official source

  3. 19 November 2026 · version 2.1.329 · Hooks

    Before: Before 2.1.329, the Claude Code changelog listed no trust dialog warning saying where a folder's hooks are declared.

    Now: From 2.1.329, the trust dialog warns where a folder's hooks are declared, and a warning appears when hooks in managed settings fail to load, according to the changelog.

    Collected automatically on 20 November 2026 from the official changelog. Official source

  4. 19 November 2026 · version 2.1.328 · Hooks

    Before: Before 2.1.328, the Claude Code changelog listed "onFailure": "block" only for command and HTTP hooks, not for mcp_tool hooks.

    Now: From 2.1.328, mcp_tool hooks accept "onFailure": "block", so a hook whose call fails blocks the action, according to the changelog.

    Collected automatically on 19 November 2026 from the official changelog. Official source

  5. 17 November 2026 · version 2.1.327 · MCP

    Before: Before 2.1.327, the Claude Code changelog listed no way to add an MCP server from JSON read on standard input.

    Now: From 2.1.327, Claude Code can add an MCP server from JSON read on standard input so tokens stay off the command line, not inside a session, according to the changelog.

    Collected automatically on 18 November 2026 from the official changelog. Official source

  6. 6 November 2026 · version 2.1.319 · Permissions

    Before: Before 2.1.319, Claude Code had no permissions.denyInsteadOfPrompting setting, according to the changelog.

    Now: From 2.1.319, permissions.denyInsteadOfPrompting denies a tool call that would wait on a permission prompt and the turn continues, according to the changelog.

    Collected automatically on 7 November 2026 from the official changelog. Official source

  7. 4 November 2026 · version 2.1.318 · MCP

    Before: Before 2.1.318, deniedMcpServers URL entries did not block matching Anthropic-provided servers and connectors in cloud sessions, according to the changelog.

    Now: From 2.1.318, deniedMcpServers URL entries also block matching Anthropic-provided servers and connectors in cloud sessions, according to the changelog.

    Collected automatically on 6 November 2026 from the official changelog. Official source

  8. 3 November 2026 · version 2.1.317 · Approval mode

    Before: Before 2.1.317, the changelog lists no check before a web or shell tool call sent the account email address to the network.

    Now: From 2.1.317, Claude Code asks before a web or shell tool call sends the account email address to the network, according to the changelog.

    Collected automatically on 6 November 2026 from the official changelog. Official source

  9. 31 October 2026 · version 2.1.316 · Approval mode

    Before: Before 2.1.316, server-managed settings for Team and Enterprise logins applied after an approval prompt, according to the changelog.

    Now: From 2.1.316, server-managed settings for Team and Enterprise logins apply without an approval prompt, according to the changelog.

    Collected automatically on 6 November 2026 from the official changelog. Official source

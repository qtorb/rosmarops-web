The RosmarOps Control Baseline

Criteria version 4

Seven yes-or-no questions about a product that puts AI agents to work: what it does out of the box, what its agents inherit, where the keys are, and whether the work it does on its own can be seen and stopped. It is not a score and it does not say whether a product is good or bad. It says whether the minimum needed to control it exists and is written down.

The seven criteria

No.CriterionWhat has to be trueWhen it applies
M1What it does out of the boxThe official documentation says what an agent can do without asking with the product as it comes, just installed or turned on.Always
M2The agents' questionsThe documentation says whether the product removes the approval questions from the agents it launches, and there is a documented way to keep them.Only if it launches agents made by others
M3What each agent inheritsThe documentation says what an agent receives from the place it runs in (environment variables, open sessions, keys), and there is a documented way to limit it per agent.Only if the agents run on the computer or server of whoever uses it
M4The keys of connected servicesThey are kept per connection, they can be removed one by one, and the documentation says whether the agent sees them in clear.Always
M5Work with nobody watchingRuns that are scheduled or triggered by an event can be listed and turned off one by one from the product.Always
M6StoppingOne agent can be stopped, and every run at once, from the product.Always
M7Security advisoriesThe vendor publishes its security advisories in a fixed place and says how to report a flaw to it.Always

“From the product” includes its API.

Who meets it

A product meets it when it has “Yes” on every criterion that applies to it. There is no score and no grade: only the count, for example “5 of 7”. “No answer” counts as not meeting it: if it is not written down and cannot be checked, the person using the product cannot know it either.

Families

  • Orchestrators and automationProducts that put AI agents to work for you.
  • Agents on the vendor's computerAI agents that work on a machine the vendor provides.

How it is measured

  • First, the official documentation or the official code. The sentence is cited, with its address and the date.
  • If that does not settle it, a test on a new installation or account, with invented data.
  • If neither settles it, “No answer”, with the reason.

We measure what the product allows and what it ships with, not any customer's account. Third-party sources do not count. The version or plan measured is stated. A result expires after 90 days.

If you are the vendor

  • You see your result before it is published, with the evidence for each criterion, and you have 14 days to correct it.
  • A result changes with a public source: a page of your documentation, your code or a new release. A private conversation does not count.
  • If you disagree, your public reply is linked next to the result, as it is.
  • Nothing is charged, for measuring or for anything else. If the mistake is ours, it is corrected the same day and stays in the history.

Write to albert@rosmarops.com.

What it does not say

  • How each person has the product set up
  • What the vendor does internally with the keys
  • How a model behaves when it meets a hidden instruction
  • Whether the product does its job well

Who does this

It is measured by RosmarOps, a project by Albert Garcia Pujadas. Masover, which uses this baseline to choose an orchestrator, has the same owner. No vendor pays for or sponsors anything here.

The data

Every result is in JSON, with its source and its date, and earlier ones are never deleted. You can reuse them under the CC BY 4.0 licence, citing RosmarOps.

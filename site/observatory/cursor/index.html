Cursor on Windows: what it can do on your computer

Anysphere · Code editor (IDE), Terminal program (CLI), Cloud · Reviewed on 29 October 2026

In short

As of 29 October 2026, Cursor's documentation recommends the auto_review mode. Which mode you use isn't written on your disk, so we assume that one: what would otherwise need your permission is approved or blocked by another AI model, not by you.

By default, without asking you, it can read files in the folders it works in, read files outside the folders it works in, read files anywhere on the computer from its terminal, even inside its isolated environment (sandbox) and edit files in the folders it works in.

On Windows, it keeps its configuration in 6 kinds of files. In 2 of them, keys can be written as they are, unencrypted: any program running under your user can read them.

Mode it starts in

Starting mode: auto_review

When an action needs permission, who gives it: another AI model.

Documented as the recommended default since Cursor 3.6; the mode in use is not readable from disk, so it is assumed. Cursor warns: "Auto-review is not a security boundary"; the classifier can allow a call you would have blocked.

Try it in a test environment

An empty folder isn't enough: most agents can read your whole home folder, keys included. This is how to limit what Cursor could touch:

  • Windows: open it from another user account on the computer, without your folders or keys.
  • macOS: its sandbox is on by default. Open it in a test folder.
  • Linux: its sandbox is on by default. Open it in a test folder.

A sandbox limits what it could touch; it doesn't make it harmless. In many agents it limits what it writes and where it connects, but not what it reads. With the network open, what it reads could get out.

Then run RosmarOps in that same environment: you see what the agent could touch.

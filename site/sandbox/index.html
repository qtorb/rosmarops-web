Sandbox: try an AI agent before you give it your folders

A sandbox is a closed space where an AI agent works without being able to touch what's outside it: the rest of your folders, your keys or the internet. Here you can see which agents have one, how to turn it on in yours and what changes when you do. RosmarOps doesn't set up any sandbox: it tells you what your agent could touch, with it and without it.

Which agents have one

Almost every AI agent has a sandbox, but almost none ship with it on. The table shows, agent by agent and system by system, whether it has one, whether it's on by default and whether it cuts off the internet.

See the table

Turn it on in your agent

Each template is a text you copy and paste into your agent: it shows you the change and asks you before saving it. It turns on the sandbox, limits what it can read and, where possible, cuts off the internet.

Antigravity CLI

macOS and Linux

Template

Add these settings to my Antigravity CLI configuration (~/.gemini/antigravity-cli/settings.json), without changing anything else. Show me the change before saving it.

{ "enableTerminalSandbox": true, "toolPermission": "proceed-in-sandbox" }

What it doesn't cover

  • MCP servers and reading web pages follow its permission rules. The domains you allow for reading web pages are also open to commands in the sandbox.
  • If you let a command leave the sandbox, it runs on your computer with all your permissions.
  • If your system lacks the sandbox it needs, the setting does nothing and doesn't warn you.
Try it just this once

Opens Antigravity CLI with the sandbox on for this session only: it doesn't change its settings, and when you close it everything goes back to how it was.

agy --sandbox

Claude Code

macOS and Linux

Template

Add these settings to my Claude Code configuration, each in the file named on its first line, without changing anything else. Show me the change before saving it.

// ~/.claude/settings.json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "disableAutoMode": "disable",
    "disableBypassPermissionsMode": "disable",
    "blockReadsOutsideWorkingDirectories": true,
    "allow": [
      "Bash(npm run lint)", "Bash(npm run test *)",
      "Bash(git status)", "Bash(git diff)"
    ],
    "ask": [
      "Edit(~/.codex/**)", "Edit(**/.codex/**)",
      "Edit(~/.cursor/**)", "Edit(**/.cursor/**)",
      "Edit(~/.cline/**)", "Edit(**/.clinerules/**)",
      "Edit(~/.gemini/**)", "Edit(**/.gemini/**)",
      "Edit(~/.grok/**)", "Edit(**/.grok/**)", "Edit(~/.hermes/**)",
      "Edit(~/AppData/Roaming/**)",
      "Edit(**/AGENTS.md)", "Edit(**/CLAUDE.md)", "Edit(**/GEMINI.md)",
      "Edit(**/.github/copilot-instructions.md)"
    ],
    "deny": ["WebFetch", "WebSearch", "Bash(curl *)", "Bash(wget *)"]
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "autoAllowBashIfSandboxed": false,
    "network": { "allowedDomains": ["registry.npmjs.org", "github.com"], "strictAllowlist": true },
    "filesystem": { "denyRead": ["~/.ssh", "~/.aws"] },
    "credentials": { "files": [ { "path": "~/.aws/credentials", "mode": "deny" }, { "path": "~/.ssh", "mode": "deny" } ] }
  }
}

// .claude/settings.json
{ "sandbox": { "filesystem": { "denyRead": ["~/"], "allowRead": ["."] } } }

What it doesn't cover

  • The sandbox only covers the terminal. Its tools for reading, editing and opening web pages work outside it: the template limits them with their own rules.
  • Hooks, the MCP servers on your computer and the status line command run outside the sandbox.
  • Commands you list in excludedCommands run outside the sandbox.
  • Commands you type yourself with ! in front run outside the sandbox.
  • The template leaves registry.npmjs.org and github.com open: what the terminal reads from the project could go out to them.
Try it just this once

Opens Claude Code with the sandbox on for this session only: it doesn't change its settings, and when you close it everything goes back to how it was.

claude --settings '{"sandbox":{"enabled":true,"failIfUnavailable":true,"allowUnsandboxedCommands":false,"autoAllowBashIfSandboxed":false,"network":{"allowedDomains":[],"strictAllowlist":true},"filesystem":{"denyRead":["~/"],"allowRead":["/RUTA/DEL/PROYECTO"]}},"permissions":{"blockReadsOutsideWorkingDirectories":true,"deny":["WebFetch","WebSearch"]}}'

Linux: Needs: bubblewrap and socat.

Replace /RUTA/DEL/PROYECTO with your project's path.

Source: Anthropic, read on 16 November 2026.

Windows

On Windows, Claude Code has no sandbox: open it from another user account on the computer, without your folders or keys.

Source: Anthropic, read on 16 November 2026.

Codex

macOS and Linux

Template

Add these settings to my Codex configuration (~/.codex/config.toml), without changing anything else. Show me the change before saving it.

default_permissions = "p2"
[permissions.p2.filesystem]
":minimal" = "read"
[permissions.p2.filesystem.":workspace_roots"]
"." = "write"
"**/*.env" = "deny"
[permissions.p2.network]
enabled = false

What it doesn't cover

  • Web search doesn't go through the sandbox.
  • App and connector calls work outside the sandbox.
  • MCP servers work outside the sandbox.
  • The browser and Computer Use work outside the sandbox.
  • The sandbox doesn't cut Codex's own connection to its service.
  • Linux: The files you block are fixed when each command starts: a file created later can be read.
Try it just this once

Opens Codex with the sandbox on for this session only: it doesn't change its settings, and when you close it everything goes back to how it was.

codex --sandbox workspace-write -c sandbox_workspace_write.network_access=false

Cursor

macOS and Linux

Template

In Cursor's settings (Settings > Agents > Approvals & Execution), choose the «Allowlist» mode, leave its list empty and turn on the sandbox.

Add these settings to my Cursor configuration, each in the file named on its first line, without changing anything else. Show me the change before saving it.

// ~/.cursor/sandbox.json
{ "readBoundary": "workspace", "networkPolicy": { "default": "deny", "allow": ["registry.npmjs.org"] } }

What it doesn't cover

  • Commands you add to its allowlist and fetching web pages run outside the sandbox.
  • It can change the settings and instructions of other agents inside the project.
  • MCP servers work outside the sandbox.
  • On Linux it needs Landlock v3; if the system doesn't have it, it goes back to asking you before each command.

Source: Anysphere, read on 16 November 2026.

Windows

On Windows, Cursor has no sandbox: open it from another user account on the computer, without your folders or keys.

Source: Anysphere, read on 16 November 2026.

Gemini CLI

macOS and Linux

macOS

Template

Add these settings to my Gemini CLI configuration, each in the file named on its first line, without changing anything else. Show me the change before saving it.

// ~/.gemini/settings.json
{ "tools": { "sandbox": true, "sandboxNetworkAccess": false } }

On macOS, this setting doesn't go in a file: start Gemini CLI like this every time.

SEATBELT_PROFILE=strict-proxied gemini

What it doesn't cover

  • Its documentation doesn't say whether MCP servers, fetching web pages and hooks go through the sandbox.
  • On macOS, the template's profile sends the network through a proxy, and its documentation doesn't say how to set that proxy.

GitHub Copilot in VS Code

macOS and Linux

Template

In VS Code, open the settings and set:

"chat.agent.sandbox.enabled": "on",
"chat.agent.sandbox.network.allowNetwork": false,
"chat.agent.sandbox.fileSystem.allowDevToolAccess": false,
"chat.agent.sandbox.fileSystem.userConfiguredPaths": { "deniedPaths": ["~/.ssh", "~/.aws"] },
"chat.agent.sandbox.allowUnsandboxedCommands": false

What it doesn't cover

  • VS Code's own tools that don't launch commands don't go through the sandbox: they use their own checks.
  • MCP servers that VS Code doesn't start work outside the sandbox.
  • Inside the sandbox, commands get your git and gh credentials by default.
  • Its documentation doesn't say whether it can read the rest of your home folder: the template only blocks ~/.ssh and ~/.aws.

Source: GitHub, read on 16 November 2026.

Grok Build

macOS and Linux

Template

Add these settings to my Grok Build configuration (~/.grok/config.toml), without changing anything else. Show me the change before saving it.

[ui]
permission_mode = "ask"

[permission]
rules = [
  { action = "allow", tool = "bash", pattern = "npm run lint" },
  { action = "allow", tool = "bash", pattern = "npm run test *" },
  { action = "allow", tool = "bash", pattern = "git status" },
  { action = "allow", tool = "bash", pattern = "git diff" },
  { action = "deny",  tool = "webfetch" },
]
deny = ["WebSearch"]

[sandbox]
profile = "strict"

[compat.claude]
hooks = false

[compat.cursor]
hooks = false

What it doesn't cover

  • On macOS, the sandbox doesn't cut the network for commands.
  • The sandbox doesn't cut the connection to the model or its web tools.
  • Web search may stay open: its documentation only confirms it's cut when you start it with --deny WebSearch.
Try it just this once

Opens Grok Build with the sandbox on for this session only: it doesn't change its settings, and when you close it everything goes back to how it was.

grok --sandbox strict --disable-web-search --deny WebFetch

Linux: Needs: Linux 5.13 or later.

Source: xAI, read on 16 November 2026.

Windows

On Windows, Grok Build has no sandbox: open it from another user account on the computer, without your folders or keys.

Source: xAI, read on 16 November 2026.

What it doesn't cover

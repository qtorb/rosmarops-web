Almost every AI coding agent has a mode that skips the questions. Here is what it does, who can switch it on and how to tell whether it is on, on your computer.

Video (in Spanish, with English subtitles): https://www.youtube.com/watch?v=JUpfX5Gt9CI

What it does

With factory settings, an agent such as Claude Code, Codex or Gemini CLI asks you before doing something that matters: running a command, touching a file, going out to the internet. You read and accept. It is slower, but you decide.

The accept-everything button removes those questions. The agent does whatever it thinks is needed, without waiting for you.

What each agent calls it

  • Claude Code: the launch option --dangerously-skip-permissions, which puts it in bypassPermissions mode.
  • Gemini CLI: YOLO mode (--yolo).
  • Codex: the option --dangerously-bypass-approvals-and-sandbox, which skips approvals and the sandbox at once. In its configuration, sandbox_mode: danger-full-access and approval_policy.
  • Cursor: «Run Everything» mode, instead of the list of allowed commands.
  • Cline: its YOLO switch.

Why it exists

Because it works. An agent that does not ask finishes sooner and keeps working while you are away. For a short task, in a folder with nothing important in it, it can make sense.

The problem is what stays within its reach. An agent without questions works with your permissions: it sees your home folder, your keys and the internet. If it reads an instruction hidden in a web page or a README, it runs it without anyone seeing it happen.

Who can switch it on

There are three ways, and only one is obvious.

  1. You. You start the agent with that option, or leave it set in your configuration.
  2. An orchestrator. Some launch your agents with the button already pressed. Paperclip, for example, starts Claude Code with --dangerously-skip-permissions. More on agent orchestrators.
  3. A file inside the project. Here each agent is different: - Since version 2.1.257, Claude Code does not let a project's configuration turn on the no-questions mode: bypassPermissions and auto only count when they come from your user configuration or the managed one. The project can still allow specific commands. - Codex only loads a project's configuration if that project is trusted. - Gemini CLI only takes a project's settings into account if the folder is trusted.

That is why it pays to think twice before trusting a repository you have just cloned.

Your organization can switch it off

In Claude Code, managed settings switch it off for everyone with disableBypassPermissionsMode. In Gemini CLI, with security.disableYoloMode. If you work in a team, it is worth asking.

How to use it sensibly

  1. Do not leave it on by default: switch it on for one task and off afterwards.
  2. If you use it, do so with the sandbox on and in a folder with no keys.
  3. Before trusting a project, look at the configuration it brings.
  4. If you use an orchestrator, look at how it launches your agents.
  5. Check now and then which of your agents has it on.

That last one is what RosmarOps is for: it reviews your agents' configuration and tells you which ones can act without asking you, where that was switched on and what they can reach, and nothing leaves your computer unless you approve it.

The accept-everything button is not bad. It is powerful. What matters is knowing when it is pressed and who pressed it.

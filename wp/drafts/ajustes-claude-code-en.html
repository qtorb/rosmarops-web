Claude Code keeps your personal settings in ~/.claude/settings.json (on Windows, %USERPROFILE%\.claude\settings.json), and each project's settings in .claude/settings.json, inside the project folder.

The files you can edit

  • Your settings, for all your projects: ~/.claude/settings.json. On Windows, ~/.claude is %USERPROFILE%\.claude.
  • The project's, shared with the team: .claude/settings.json, in the project folder. They go into git with the rest of the code.
  • Yours in that project: .claude/settings.local.json. When Claude Code creates this file, it sets git to ignore it.
  • The rest of the configuration: ~/.claude.json. It holds your account details, the MCP server configuration, each project's state (such as trust decisions) and the global options that /config writes.
  • The project's MCP servers: .mcp.json, in the project folder.

The ones your organization sets

You do not create or edit managed settings, and no user or project setting overrides them. If they exist, they are here:

  • macOS: /Library/Application Support/ClaudeCode/managed-settings.json
  • Linux and WSL: /etc/claude-code/managed-settings.json
  • Windows: C:\Program Files\ClaudeCode\managed-settings.json. Claude Code does not read the old path, C:\ProgramData\ClaudeCode\managed-settings.json.

They can also arrive through the system's device management (on macOS, the com.anthropic.claudecode domain; on Windows, the registry, under HKLM\SOFTWARE\Policies\ClaudeCode or HKCU\SOFTWARE\Policies\ClaudeCode) or from the Claude admin console.

Which one wins

From strongest to weakest: managed, what you pass with --settings at launch, yours in the project, the project's and, last, your user settings.

What to check

settings.json and .claude.json can hold unencrypted keys. Open them and look at what is there. The Observatory's Claude Code page lists what each one holds and what Claude Code does with factory settings.

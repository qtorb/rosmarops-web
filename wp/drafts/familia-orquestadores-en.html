An orchestrator or an automation tool puts several AI agents to work for you. What each agent can do without asking is no longer decided in the agent.

If you use an AI agent to program, you know how it goes: you ask for something, it asks you before the important steps, and you decide. Each agent brings its own questions and its own settings.

The next step is not launching it yourself. There are products that do it for you: they split a task among several agents, start them at a set time or when an email arrives, and keep going when you are not looking. There are three kinds:

  • Orchestrators, which coordinate several agents as if they were a team.
  • Workflow automation, which chains steps and services and puts agents inside.
  • No-code builders, where you put an agent together without programming.

Some are installed on your computer or your server. Others are contracted in the vendor's cloud.

What changes

When you launch the agent, its questions reach you. When another program launches it, that program decides which settings it starts with, which keys it hands over and whether its questions reach anyone.

So what an agent can do without asking is no longer decided in the agent. It is decided in the product that launches it. And it is easy to miss: you keep thinking of your usual agent, with its usual questions, and that is no longer the case.

The seven questions

They are the ones in the RosmarOps Control Baseline. They are answered yes or no, with the product's official documentation, its public code or a test:

  1. Out of the box. Does it say what an agent can do without asking you, as it comes?
  2. The agents' questions. If it launches agents made by others, do they keep their questions, or does it clearly say it removes them?
  3. What each agent inherits. Does it say which folder, which environment and which keys each one receives?
  4. The keys. Are they kept per connection, can they be removed one by one, and does it say whether the agent sees them?
  5. With nobody watching. Can you see the list of what starts on its own and turn each item off?
  6. Stopping. Can you stop one agent, and all of them at once?
  7. Security advisories. Does it publish its advisories in a fixed place and say how to report a flaw?

Not all of them apply to every product. The second only counts if the product launches agents made by others; the third, if it runs on your machine.

Why yes-or-no questions

Because we do not measure whether a product is good. We measure whether the person using it can know what it does. A product can be very well built and not say so anywhere; for whoever installs it, the result is the same as if it were not.

And because a missing answer is almost always fixed with one page of documentation. That is why we tell the vendor fourteen days before publishing, and say which line would change the result.

What you can do today

If you already use an orchestrator or an automation tool with agents inside, look in its documentation for the first question: what an agent does without asking you, as it comes. It is the one that changes most from one product to another.

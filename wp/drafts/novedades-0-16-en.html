The first time you run RosmarOps on a computer with several agents, the report makes an impression, and not always a good one. It used to end in a long list of findings, one per file and per agent, and it was hard to know where to start.

Look closer and many of those findings were the same problem seen from different places. If you let your agents run commands without asking you, that shows up in each agent's settings and in every project where you turned it on. Each place was a finding. But the problem is one, and changing one setting fixes it.

With 0.16.0, the report starts there. When you open it you see three blocks:

  1. Your result: the score and what it means.
  2. Your problems: findings grouped by the problem behind them, each with the places where it shows up.
  3. How to stop them coming back: the setting to change, and a template you can paste into your agent so it changes it for you.

You read less and you know what to do first. That's what a report is for.

The rest of this version is fixes that come from the people testing it:

  • On Ubuntu, Firefox from the Snap store couldn't open reports, because they were saved in a hidden folder. They now go to ~/RosmarOps, and your earlier ones are moved there once.
  • When RosmarOps updates, it checks that the new version is really the one you installed. That check now asks you in your language.
  • When a project takes too long to review, the report says «at least N findings» and how many projects didn't finish, instead of a number that looks complete.

And one thing you don't see: before we publish a version, we install it from scratch and update it from the previous one, on Windows, macOS and Ubuntu. If one of those journeys fails, the version doesn't ship. It already stopped one release this week.

If you already use RosmarOps, update and run a review: the first screen is the new one. If you don't have it yet: on Windows, from the Microsoft Store or GitHub; on macOS and Linux, with brew install qtorb/rosmarops/rosmarops or from GitHub.
